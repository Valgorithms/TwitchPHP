# TwitchPHP contributor guidance

- This is an async ReactPHP library (PHP 8.4+). Follow existing promise and Part/Collection conventions; inspect inherited members before adding client properties or methods.
- Start with `git status --short` and the current diff. Preserve other work, especially dependency constraints and ongoing API fixes. `TwitchPHP-Http` is a separate package; inspect the installed version before assuming a sibling checkout is in use.
- `composer.lock` is intentionally ignored. On a fresh checkout use `composer update`; to reproduce an existing local lock use `composer install`. Do not refresh dependencies simply to hide a failing test. `composer verify` checks manifest/lock consistency, platform requirements, dependency provenance, then the suite without installing anything.
- `composer deps:check` rejects local path dependencies by default. For intentional sibling development, run `composer deps:check -- --allow-local-paths` and the remaining checks separately; report that published dependencies have not been validated. Do not rewrite local path repositories or unrelated Composer edits.
- Use `php vendor/bin/phpunit --filter="ClassName::method"` while fixing a failure. `composer test:api` exercises repository request/response contracts, hydration, token recovery and persistence with synthetic transports. It does not contact Twitch or read `.env`. `composer test` is the broader check. CI covers Ubuntu PHP 8.4/8.5 and Windows PHP 8.4.
- API audits must distinguish expired credentials, missing scopes, wrong token kind, unavailable channel data, and parsing defects. Inspect response shape as well as status. Follow delegated helper calls before reporting an endpoint as missing. Prefer an authoritative operation/path/verb contract over regex counts or scraped prose.
- A live API check is separate from offline verification. Select endpoints explicitly by operation and side effects; include authentication refresh/persistence in that assessment. Never sweep all GETs on the assumption they are read-only. Do not print tokens, Authorization headers, `.env`, or token-bearing URLs. Keep useful checks in `scripts/` or tests, not temporary chat folders.
- Use the repository's php-cs-fixer configuration on touched files. The `tools/` directory is ignored because it holds the documentation builder; put maintained developer checks in `scripts/`.
- For docs changes, inspect `.github/workflows/docs.yml` and exercise its configured `phpdoc.dist.xml` invocation. Docs publish on release, manual dispatch, or a push whose message contains `build docs`; inspect all release workflows before publishing. A local test pass is distinct from a successful CI run or a verified published page.
